# 系统架构

## 整体流程

工作台是一个本机单进程 Node.js 应用。浏览器页面通过同源 HTTP 接口调用服务端；服务端把任务状态写入 SQLite，并按任务阶段调用模型、图片接口、浏览器控制和可选的 Paperclip。

```text
用户浏览器（127.0.0.1:4330）
        │
        ▼
本地 HTTP 服务 app/src/server.mjs
        ├── 产品、任务、稿件与调用记录 ── SQLite / app/data
        ├── 研究、写作、审查 ────────── OpenClaw + DeepSeek
        ├── 封面与正文漫画 ──────────── 火山方舟图片接口
        ├── 公众号草稿上传与数据读取 ─── ego-lite 浏览器控制
        └── 可选任务镜像 ─────────────── Paperclip（127.0.0.1:4320）
```

## 主要组件

### 页面层

`app/public/` 是原生 HTML、CSS 和浏览器 JavaScript，没有前端构建步骤。`app.js` 负责路由和页面状态，其他文件拆分产品素材、手工交付、任务过滤、错误说明和审查结果显示。

### HTTP 服务

`app/src/server.mjs` 是组合入口，默认只监听 `127.0.0.1:4330`。它负责：

- 提供静态页面和 `/api/*` 接口；
- 校验 Host、Origin 和每次启动生成的操作令牌；
- 初始化存储、模型运行时、浏览器、调度器和 Paperclip；
- 每 1.5 秒推进一个可执行任务或待上传草稿；
- 每 30 秒检查周期任务，每 5 秒检查一次可选 Paperclip 连接。

### 内容工作流

`workflow.mjs` 保存任务阶段和断点。典型任务依次经过：

1. 根据产品资料和历史内容确定方向；
2. 从公开来源收集文章线索；
3. 针对每个平台生成独立稿件；
4. 由另一角色审查事实、夸大表述和平台适配；
5. 生成封面与正文漫画，组合预览；
6. 等待用户修改、退回或批准；
7. 微信稿件仅上传草稿箱，其他平台导出后手工处理；
8. 用户登记真实发表链接后再安排数据收集。

已完成阶段会写入数据库和运行账本。网络中断时可以续跑，但付费请求结果不明时会停止，避免自动重试造成重复费用。

### 外部能力

- `agent-runtime.mjs`：启动隔离的 OpenClaw 角色，经本地限额代理调用 DeepSeek。
- `cover-agent.mjs`：调用火山方舟图片接口并校验图片类型、尺寸和请求结果。
- `browser.mjs`：组织账号检查、公众号编辑器填充、草稿保存和只读数据采集。
- `paperclip.mjs`：把工作台任务镜像到 Paperclip，也可导入分配给运营负责人的待办。
- `scheduler.mjs`：创建周期内容任务和发表后 24/48/72 小时数据任务。

## 数据存储

业务对象统一存入 `app/data/operator.sqlite` 的对象表，包括产品、文档、任务、稿件、审批、账号、效果数据和事件。图片及调用账本保存在 `app/data/` 的子目录中。

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 业务对象 | `app/data/operator.sqlite` | 当前工作台的主要数据源 |
| 图片与导出文件 | `app/data/assets/` | 内容寻址并与稿件、产品绑定 |
| 外部服务配置 | 根目录 `.env` | 模型密钥、模型名称、服务地址和默认调用预算的唯一来源 |
| 模型调用账本 | `app/data/runtime/` | 用于费用保护和异常恢复 |
| Paperclip 数据 | `research/runtime-lab/state/paperclip/` | 独立 PostgreSQL 实例 |

## 安全边界

- 服务只接受本机 `127.0.0.1` 或 `localhost` 请求。
- 写请求必须携带当前进程生成的操作令牌，并校验同源地址。
- 导入文档限制格式、大小、压缩条目和外部关系。
- 离线导出不读取远程图片，只嵌入已登记且校验过的本地资源。
- 浏览器自动发表已禁用；微信只保存草稿，最终发表由用户确认。
- 账号密码和 Cookie 不写入业务数据库，浏览器登录状态由浏览器工具管理。
